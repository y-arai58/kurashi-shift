# くらしシフト

福岡市の公的支援を、ユーザーの暮らしの条件に照らして案内するWebアプリです。

## 完成している範囲

- ホーム → 3問のプロフィール → 支援候補 → 条件に応じた追加質問 → 制度詳細・公式情報
- 一致／未確認／不一致を分けた説明。候補件数に不一致・期限超過を含めない
- 各制度の質問だけ回答し、元の制度詳細へ戻る導線
- 出産・市内での賃貸への転居・住宅購入のシミュレーション
- 今と変化後の候補追加・除外・確認条件変更の比較（元の回答を変更しない）
- ブラウザーの戻る／進むと制度詳細への直接リンク（ハッシュによる画面遷移）
- スマートフォン向けレイアウト、キーボード操作、画面遷移時の見出しへのフォーカス

現在は子ども医療費助成、児童手当、子育て世帯市内引越し応援事業、就学援助、高齢者乗車券の5制度です。掲載範囲を網羅的とは表現しません。市外の制度比較、将来の制度改正の予測、個別の受給金額計算、オンライン申請の代行は対象外です。

## 起動と検証

Node.js 24推奨（テストはNode.js標準のTypeScript実行機能を使用）。

```sh
npm ci
npm run dev
npm test
npx tsc --noEmit
npx oxlint app components/kurashi-shift-app.tsx lib tests
npm run build
```

技術構成はReact 19、TypeScript、Vinext、Tailwind CSS、既存のBase UI / shadcnコンポーネント。公開先はSitesのCloudflare Workers対応ビルドです。

## 判定と拡張

- `lib/domain.ts`: プロフィール・条件・制度・判定の型
- `lib/programs.ts`: 制度の公式情報、条件、出典、最終確認日、申請に向けた手順
- `lib/evaluate.ts`: 副作用のない条件照合、受付・鮮度判定、プロフィール間の差分
- `lib/profile.ts`: プロフィール変更時の依存回答のクリア、シミュレーションでのコピー
- `lib/questions.ts`: 適用条件つき追加質問。制度の条件と同じプロフィール項目で関連づけ
- `components/kurashi-shift-app.tsx`: 画面と操作
- `tests/diagnosis.test.ts`: 未回答、除外、期日、プロフィール変更、差分の回帰テスト

`eligible`は**実装済みの主な条件がすべて一致**した状態で、受給確定や統計的確率ではありません。`needs-info`は未確認条件あり、内部名`future`は既存コードとの互換性のため残した不一致状態です。不一致を将来受給できるとの意味では表示しません。スコアは並び順専用で、受給確率としては表示しません。

実装していない重要要件（住宅・校区、学校種別など）は常に未確認として残し、公式ページへ案内します。「所得要件に該当しないと思う」という自己判断だけで、就学援助の個別審査への可能性を除外しません。

他自治体を加える場合は、先に自治体ごとの公式制度と適用範囲を接続し、プロフィールの居住地を具体的な自治体IDへ拡張してください。未収集の自治体を「支援0件」と比較しないでください。差分計算は独立しているため同じ関数を再利用できます。

## 情報を更新する手順

1. 各制度の`officialUrl`を開き、年度・対象・金額・除外・受付状況を確認する。
2. `sourceUpdatedAt`（公式更新日）と`verifiedOn` / `lastVerified`（実際に確認した日）を分けて更新する。確認せず確認日だけ進めない。
3. `applicationDeadline`は公式の最終日を日本時間のISO日付で記録する。募集期限と転居から1年など個別期限を区別する。予算による早期終了は公式確認が必要。
4. `reviewAfter`を次の再確認日に設定する。現在は2026-10-07。過ぎると「再確認が必要」に切り替わり、主な条件に一致した制度も未確認扱いになる。
5. 年度の期限超過後は候補から除外し、詳細では期限経過と最新年度の確認を案内する。新年度のデータへ人が更新する。
6. 変更した条件の境界テストを追加し、テスト・型検査・ビルド後に公開する。

自動クロールや自動的なデータ更新は行いません。2026-09-07に確認した公式URLはすべて制度データに保存しています。高齢者乗車券は2026-09-30、市内引越しは2027-02-28、就学援助は2027-03-31が現在掲載中の年度の期限です。

## 入力の取り扱い

回答はReactのメモリー内だけで扱います。URL・ブラウザーストレージ・アプリのサーバーへは保存しません。再読み込みで消去され、個人情報を含む画面へ戻ってもプロフィールの入力を求めます。編集は更新ボタンで反映し、戻る操作では確定しません。サイト配信基盤のアクセス管理や一般的なアクセスログとは別の取り扱いです。

WebMCPの`set_basic_profile`は、UIと共通の検証・判定関数でプロフィールを設定して結果を表示します。未対応地域、追加項目、不正な選択肢を明示的に処理します。
